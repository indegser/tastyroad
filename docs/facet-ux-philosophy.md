# Tastyroad Facet UX Philosophy

## 목적

Tastyroad의 패싯은 맛집 목록을 탐색하기 위한 보조 장치다. 검색어가 사용자의 의도를 가장 먼저 받는 입력이고, 패싯은 그 결과를 식당명 초성, 지역, 채널 같은 안정적인 축으로 좁히는 역할을 한다.

패싯은 카테고리 페이지를 만드는 도구가 아니라, 검색 결과 안에서 방향을 빠르게 바꾸는 도구로 다룬다.

## 기본 원칙

- 검색을 먼저 둔다. 식당명, 동네, 메뉴, 채널을 바로 입력할 수 있어야 한다.
- 패싯 최상위 축은 적게 유지한다. 현재 공개 목록의 기본 축은 `가나다`, `지역`, `채널`이다.
- 옵션이 늘어나도 최상위 패싯을 계속 늘리지 않는다. 하위 옵션은 패싯 안에 넣고, 새 최상위 축은 사용자가 반복해서 찾는 독립적인 탐색 기준일 때만 추가한다.
- 선택된 값은 항상 목록 바깥에서 다시 확인하고 제거할 수 있어야 한다.
- 필터 변경은 페이지를 1페이지로 되돌린다. 좁혀진 결과에서 이전 페이지 번호가 빈 결과를 만들지 않게 하기 위해서다.
- 링크 기반으로 동작한다. 공유 가능한 URL, 브라우저 뒤로가기, 서버 렌더링 결과가 모두 같은 상태를 가리켜야 한다.

## PC 원칙

PC는 29CM PC 검색 결과처럼 좌측 레일을 쓴다.

이유:

- PC는 가로 공간이 충분해서 결과 목록과 필터를 동시에 보여줄 수 있다.
- 사용자는 목록을 스캔하면서 좌측에서 조건을 반복 조정할 수 있다.
- 패싯이 늘어날수록 상단 가로 바는 결과 영역을 밀어내지만, 좌측 레일은 탐색 밀도를 안정적으로 유지한다.
- 이커머스 검색에 익숙한 사용자는 좌측 레일을 필터 영역으로 자연스럽게 인식한다.

PC 레일 규칙:

- 레일은 결과 목록 왼쪽에 고정된 보조 영역으로 둔다.
- 검색창과 활성 필터 칩은 레일 바깥 상단에 둔다. 검색과 현재 상태는 전체 결과의 맥락이기 때문이다.
- 레일 안에서는 `가나다`, `지역`, `채널`을 세로로 배치한다.
- 레일의 패싯 그룹은 처음에는 접힌 상태로 시작한다. 사용자가 필요한 축만 열어 결과 목록을 덜 밀어내게 하기 위해서다.
- 지역은 `지역권`과 `세부 지역`을 하나의 패싯 안에서 다룬다. 지역 패싯을 둘로 쪼개면 탐색 축이 불필요하게 늘어난다.
- 채널은 복수 선택을 허용하고, 가나다와 지역은 단일 선택 후 다시 누르면 해제된다.

## 모바일 원칙

모바일은 29CM 모바일 검색 결과처럼 가로 칩과 접힌 패널 흐름을 쓴다.

이유:

- 모바일에서 좌측 레일은 결과 목록을 밀어내고 화면 폭을 낭비한다.
- 사용자는 검색 결과를 보다가 상단의 작은 필터 칩으로 조건을 열고 닫는 흐름에 익숙하다.
- 패싯 상세 옵션은 한 번에 하나의 패널로 집중해서 보여주는 편이 터치 조작에 안정적이다.

모바일 규칙:

- 최상위 패싯은 `가나다 | 지역 | 채널`처럼 가로로 둔다.
- 처음에는 접힌 상태로 시작한다.
- 선택값은 활성 필터 칩으로 노출해서 사용자가 현재 조건을 바로 제거할 수 있게 한다.
- 패싯 상세는 모바일 화면에서 결과 목록보다 잠시 우선하는 편집 영역으로 다룬다.

## 확장 기준

새 패싯을 추가하기 전에 다음 질문을 통과해야 한다.

- 사용자가 이 조건으로 반복해서 맛집을 찾을 가능성이 높은가?
- 검색어로 대체하기 어려운 구조화된 기준인가?
- 결과 수를 의미 있게 줄이는가?
- PC 좌측 레일과 모바일 접힌 패널 안에서 모두 설명 없이 이해되는가?
- 활성 칩으로 짧게 표시할 수 있는가?

이 기준을 통과하지 못하면 검색 품질이나 결과 카드 정보를 개선하는 쪽을 먼저 검토한다.
