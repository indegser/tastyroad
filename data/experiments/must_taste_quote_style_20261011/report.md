# Must-taste 자막 말투 진단 및 실험 — 2026-10-11

작업 브랜치: `codex/must-taste-quote-style`, 기준 커밋: `1c928f8`.

## 확인한 원인

츠지한 압구정의 원문은 “선도가 너무 좋은 거야”, “잘 지은 밥이랑 섞이는 느낌이 너무 좋더라”, “다시 오고 싶어지더라고”다. 저장된 공개 문구는 “맛이 인상적입니다”, “다시 오고 싶어졌다고 했습니다”로 화자와 말투를 바꾼 요약이다.

원래 작성에 사용된 `/tmp/prepare_tsuji_taste.py`의 문자열과 DB `repaired_reason`이 정확히 일치한다. 같은 방식으로 `/tmp/prepare_choiza_short_taste.py`의 쇼츠 3개와 `/tmp/prepare_nongol_taste.py`의 일반 영상 2개 공개 문구도 정확히 일치함을 AST 문자열 비교로 확인했다. 이 파일들은 요약문을 `result.json`에 직접 넣었다. 검증기는 원문 근거·형식·길이를 검사하며, 화자의 말투가 유지됐는지는 검사하지 않는다. 생산 스크립트의 SHA-256과 대조 결과는 [results.json](results.json)에 보존했다.

따라서 확인된 문제는 결과 작성 단계에서 설명조 문구가 들어가고, 원문과의 편집 대조 없이 통과한 것이다. **쇼츠라는 형식만의 문제로 볼 수 없다.** 같은 시기 일반 영상의 논골집, 3일한우국밥, 진미식당에도 같은 유형의 문구가 있고, 이전 쇼츠에는 구어체를 보존한 문구가 있다.

단일 식당용 안내에는 이미 충분한 자막 편집 지침이 있었다. 별도로, 묶음 영상의 생성 안내에는 `source-preserving`이라는 짧은 지시만 있고 실제 편집 지침이 빠진 불일치를 발견했다. 츠지한의 직접 작성 스크립트가 이 묶음 안내를 사용했다는 증거는 없으므로, 이 불일치를 츠지한의 확정 원인으로 주장하지 않는다.

## 수정 범위

- 기존 자막 편집 지침을 쇼츠·묶음 영상·결과 JSON 조립 스크립트에도 적용하도록 명시했다. 리뷰의 해설문을 공개 문구로 옮기지 않도록 했다.
- 묶음 영상용 생성 안내에 기존 단일 식당용 편집 지침을 넣었다. 원래 “훌륭했습니다”라고 한 발언은 그대로 존댓말이어도 된다는 구분을 덧붙였다.
- 작업자 첫 결과를 원문과 대조해 보고 확장/저장하도록 했다. 원문 자체가 끊겨 있으면 기존 원문 구간 선택으로 돌아가도록 했다.

단일 식당용 생성 코드, 점수/메뉴 선정 규칙, DB 적용/검증 코드는 변경하지 않았다. 기존 리뷰/선정 프롬프트 내용도 마지막 빈 줄을 제외하고 동일하다. `했습니다` 금지어 검사나 쇼츠 전체 재작성 규칙은 추가하지 않았다.

## 50개 문구 비교

동결한 성시경 기준 자료는 30편·30쌍·69개 메뉴다. 그중 각 쌍의 첫 메뉴 30개에 목적별 20개 문구를 더해 총 50개를 편집 실험했다. 목적별 표본은 문제 쇼츠 5개, 문제 일반 영상 4개, 기존 쇼츠 말투 대조 5개, 기존 일반 영상 말투 대조 2개, 존댓말 원문 4개다. “말투 대조”는 ASR까지 완벽하다는 사전 판정이 아니다.

독립 편집 실행 A에는 현재 묶음 처리 안내, B에는 수정 안내를 제공했다. 두 실행 모두 같은 메뉴명/원문만 읽었고, 기존 공개 문구·표본 분류·상대 결과는 보지 않았다. 메뉴 선정은 고정했으며 새 메뉴를 추출한 실험은 아니다. 별도 검토자가 원문과 세 종류의 문구(기존 저장/A/B)를 사례마다 무작위 X/Y/Z로 받아 판정했다.

| 문구 | 통과 | 경미한 문제 | 실패 |
|---|---:|---:|---:|
| 기존 저장 | 20 | 11 | 19 |
| 현재 안내 재실행 A | 47 | 3 | 0 |
| 수정 안내 재실행 B | 48 | 2 | 0 |

수정안에서 목적별 문제 쇼츠 5개와 일반 영상 4개는 모두 직접 발언 형태로 나왔다. 원래 존댓말인 대조 4개도 모두 통과했다. 정상 판정을 받은 기존 문구가 수정안에서 중대한 실패로 바뀐 사례는 없었지만, `case_036` 제육볶음은 기존 통과 → 수정안 경미한 문맥 문제로 바뀌었다. `case_044` 불고기도 끊긴 ASR 구절을 남겨 경미한 문제로 판정됐다.

현재 안내 A로도 츠지한은 자연스러운 직접 발언으로 재생성됐다. 47/50과 48/50의 작은 차이는 단일 실행의 생성 변동과 구분할 수 없다. 이 결과를 “기존 편집 지침 자체가 잘못됐다”거나 “새 문체 프롬프트가 통계적으로 우월하다”는 증거로 사용하지 않는다. 수정의 목적은 이미 있는 편집 과정을 모든 결과 경로에 드러내고 누락을 발견하는 것이다.

## 반복 실행 및 원문 재선택

초기 경미한 문제 2개와 정상/존댓말/문제 쇼츠 대조를 포함한 12개를 새 독립 실행에서 같은 수정 안내로 다시 편집했다. 별도 검토자의 판정은 **통과 8, 경미한 문제 3, 실패 1**이었다. 설명조로의 변환은 없었으나, ASR/지시어/생략된 문맥 문제는 남았다. 이 표본은 의도적으로 고른 12개이며 일반적인 실패율을 뜻하지 않는다.

실패한 `case_044`는 원문 자체가 심하게 깨져 “숯이랑 좋은 고기랑. 맛있다.”처럼 연결이 끊긴 결과가 나왔다. 작업 DB의 복사본과 기존 준비 스크립트로 전체 보관 자막을 읽고, **수정하지 않은 단일 식당용 원문 선택/편집 지침**을 다시 실행했다. 별도 실행은 224–226번 구간을 선택해 다음 문구를 만들었다.

> 이쪽은 생고기를 다른 양념을 해서 바로 내는 거죠.

선택 원문은 실제 구간을 순서대로 합친 문자열과 정확히 일치하고, 보정문은 불확실한 뒷부분만 제거했다. 길이 검사와 원문 대조를 통과했다. 이 후속 문구는 담당 에이전트가 읽어 판단했으며 블라인드 판정은 아니다. 나머지 반복 결과를 임의로 고쳐 실험 점수를 높이지 않았다.

## 검증과 한계

- 기존 must-taste 단위 검사 5개, 스킬 구조 검사, 생성 프롬프트 확인, `git diff --check` 통과.
- A/B 100개와 반복 12개, 재선택 1개 문구 모두 기존 공개 문구 길이 제한/한 줄 형식을 만족한다. 의미/말투 판정은 위 독립 검토 결과로 구분한다.
- 실제 DB의 SHA-256, 단일 식당용 생성 코드 SHA-256, 적용 검증기 SHA-256이 실험 전후 동일하다. 메뉴·순위·근거·기존 공개 문구에 쓰기 작업이 없었다.
- 실험은 **고정된 메뉴의 공개 문구 편집** 범위다. 전체 영상에서 메뉴를 새로 선정하는 전체 파이프라인이나 배포를 검증한 것은 아니다.
- 모델과 검토자 판단에는 변동이 있다. 일반적인 부작용이 0이라고 보장하지 않는다. 특히 깨진 ASR은 말투 지시만으로 해결되지 않아, 첫 결과 원문 대조와 원문 구간 재선택이 필요하다.

원문, 생성 결과, 무작위 배정, 검토 메모, 생산 스크립트 해시, 반복 실험과 재선택 자료는 [results.json](results.json)에 있으며, 실제 사용한 현재/수정 프롬프트도 같은 디렉터리에 저장했다. 기존 데이터 교체나 배포는 이 작업에 포함하지 않았다.
